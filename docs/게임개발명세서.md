# 빙의했더니 영지 멸망 3년 전 게임 개발 명세서

> 문서 버전: 1.3  
> 문서 목적: 졸업프로젝트 구현을 위한 제품 기획 및 기술 명세  
> 주요 독자: 개발자, 기획자, Codex 등 코딩 에이전트  
> 기준 플레이타임: 1회 10~15분

## 0. Codex 작업 지침

이 문서는 프로젝트의 단일 기준 명세다. 구현 시 다음 우선순위를 따른다.

1. `고정 결정 사항`은 별도 승인 없이 변경하지 않는다.
2. 게임 진행, 수치 계산, 사건 선택, 엔딩 판정은 서버의 결정론적 로직으로 구현한다.
3. LLM은 NPC 대사, 태그 후보, 요약, 직업명, 에필로그 표현을 생성하지만 게임 상태를 직접 변경하지 않는다.
4. 모든 LLM 출력은 JSON Schema로 검증한 뒤 사용한다.
5. API 실패, 시간 초과, 잘못된 JSON이 발생해도 플레이를 끝까지 진행할 수 있어야 한다.
6. 기능은 아래 MVP 범위부터 구현하며, 범위 외 기능을 선행 구현하지 않는다.
7. API 키와 시스템 프롬프트는 클라이언트에 포함하지 않는다.
8. 각 작업은 테스트 가능한 작은 단위로 나누고, 완료 조건을 충족한 뒤 다음 작업으로 이동한다.

### 0.1 고정 결정 사항

- 장르: 웹소설풍 빙의·영지 경영 인터랙티브 비주얼 노벨
- 핵심 경험: 자유 대화와 결정적 선택지가 함께 만드는 짧고 반복 가능한 이야기
- 클라이언트: Godot Engine 4.x, GDScript
- 서버: C#, ASP.NET Core Web API
- 데이터베이스: SQLite, Entity Framework Core
- AI 연동: OpenAI API, 서버 측 호출
- 기본 구조: 4개 Act
- 메인 스토리: 3년 뒤 북부 마력 균열로 멸망할 영지와 주민을 구한다.
- MVP 사건 구성: 고정 핵심 사건 3개와 소소한 농사 사건 1개
- 시간 제한: 평상시 대화는 턴 수로 제한하고, 최종 위기에서만 실시간 제한을 사용한다.
- 엔딩 원칙: 서버가 플레이 성과와 성향을 판정하고 LLM이 정통·명예·이색·B급 직업과 후일담으로 표현
- 발표 안정성: 실제 API 모드와 Mock 모드를 모두 제공

### 0.2 구현 선택 가능 사항

다음 항목은 명세의 기능과 완료 조건을 지키는 범위에서 개발자가 선택할 수 있다.

- Godot 씬과 스크립트의 세부 분리 방식
- ASP.NET Core의 Controller 또는 Minimal API 방식
- DTO, Repository, Service 계층의 세부 구조
- 테스트 프레임워크와 로깅 라이브러리
- 최종 UI 색상, 애니메이션 속도, 세부 레이아웃
- OpenAI 모델명과 세부 생성 파라미터. 모델명은 코드에 직접 고정하지 않고 환경 설정으로 관리한다.

## 1. 프로젝트 정의

### 1.1 가칭

**빙의했더니 영지 멸망 3년 전**

기존 가칭인 `회귀했더니 영지 멸망 3년 전`은 주인공이 현대인으로서 판타지 인물의 몸에 들어온다는 설정과 맞지 않으므로 변경한다. 추후 제목을 다시 정하더라도 본편 설정은 `회귀`가 아니라 `빙의`를 기준으로 한다.

### 1.2 한 줄 소개

현대인이 3년 뒤 멸망할 북부 영지의 젊은 영주에게 빙의해, 영지민과 관계를 쌓고 마력 균열에 대비하며 자신의 새로운 직업과 영지의 미래를 만드는 LLM 기반 인터랙티브 비주얼 노벨이다.

### 1.3 차별점

- 고정 선택지만 누르는 대신 NPC와 자유 텍스트 대화를 주고받는다.
- 자유 대화가 성향, 관계, 사건의 세부 결과에 반영된다.
- 주요 사건과 승패는 명확한 게임 규칙으로 통제된다.
- 멸망 저지라는 선명한 목표 사이에 농사처럼 평화로운 생활 사건을 넣어 영지민에게 정을 붙이게 한다.
- 마지막에는 플레이 기록을 근거로 기사, 마탑주 같은 정통 직업부터 예상 밖의 B급 직업까지 다양한 직업과 에필로그가 생성된다.
- 좋은 플레이는 그에 걸맞은 위상과 성취로 보상하며, 이색적이거나 B급인 결과도 플레이 맥락과 인과관계를 반드시 설명한다.

### 1.4 목표 사용자 경험

플레이어는 다음 감정을 순서대로 경험해야 한다.

1. 빙의 직후, 3년 뒤의 멸망을 알고 있다는 긴박감
2. 자유롭게 말해도 NPC가 반응한다는 놀라움
3. 자신의 말과 선택이 사건을 바꿨다는 성취감
4. 자신의 실력과 플레이 방식에 어울리는 직업을 얻는 만족감 또는 예상 밖의 직업에서 오는 웃음
5. 결과 화면을 캡처하거나 다른 엔딩을 보기 위해 다시 플레이하고 싶은 마음

### 1.5 비목표

MVP에서는 다음을 목표로 하지 않는다.

- 무한한 오픈월드 서사
- LLM이 모든 사건과 규칙을 즉흥적으로 결정하는 구조
- 50개의 수작업 직업 엔딩
- 전투 액션 시스템
- 온라인 멀티플레이
- 대규모 동시 접속 서비스
- 완전한 음성 대화와 음성 합성

## 2. 게임 디자인

### 2.1 최종 목표

플레이어는 3년 뒤 열릴 북부 마력 균열에 대비해 방어력, 자금과 보급, 주민 결속, 봉인 준비를 확보하고 영지의 멸망을 막아야 한다. 위기의 원인은 처음부터 알려 주며, 범인을 찾는 추리보다 `누구를 믿고 무엇을 준비할 것인가`에 전략의 초점을 둔다.

#### 주인공의 기억 설정

- 주인공은 이 세계를 다룬 웹소설을 읽었던 현대인이다.
- 빙의한 몸의 기억을 완전히 소유하지 않으며, 사람·장소·물건을 접할 때 짧은 감각 기억만 떠오른다.
- MVP에서 중요한 기억 조각은 최대 3개로 제한한다.
- 기억은 범인을 맞히는 증거가 아니라 NPC의 사정, 생활 기술, 과거의 약속을 이해하는 대화 선택지 또는 작은 보너스로 사용한다.
- 주인공이 확실히 기억하는 미래는 `3년 뒤 균열 발생`, `세 개 봉화의 소등`, `영지 멸망`뿐이다.

### 2.2 내부 핵심 상태

수치는 기본적으로 플레이어에게 직접 노출하지 않는다. UI에서는 보고서 문장, 배경 변화, NPC 표정, 효과음 등으로 상태를 전달한다.

| 상태 | 범위 | 의미 |
| --- | ---: | --- |
| `military` | 0~100 | 병력, 성벽, 주민 대피 훈련 등 물리적 대응 능력 |
| `treasury` | 0~100 | 자금, 식량, 물자와 외부 거래 능력 |
| `legitimacy` | 0~100 | 민심, 신뢰, 영지민의 협력 의지 |
| `ward` | 0~100 | 봉화와 균열 봉인술의 준비도 |

초기값은 콘텐츠 설정 파일에서 관리한다. 모든 변화량은 서버가 허용 범위로 제한한다.

### 2.3 플레이어 성향 태그

대화에서 LLM이 태그 후보를 추출하고 서버가 허용 목록에 있는 태그만 기록한다.

- `kind`: 다정함
- `ruthless`: 냉혹함
- `persuasive`: 달변
- `observant`: 통찰
- `pragmatic`: 실리
- `reckless`: 무모함
- `eccentric`: 기행
- `threatening`: 위협적

각 태그는 0~10의 누적 점수를 가진다. 한 번의 대화에서 같은 태그는 최대 2점까지만 증가한다.

### 2.4 직업 적성

`career_affinities`는 플레이어가 무엇을 잘했는지 나타내는 숨겨진 수치다. 영지의 상태를 나타내는 `military`, `treasury`, `legitimacy`, `ward`와 분리하여 관리한다.

| 적성 | 범위 | 의미 | 대표 직업군 |
| --- | ---: | --- | --- |
| `martial` | 0~100 | 전투 지휘, 결단력, 물리적 위기 대응 | 기사, 기사단장, 장군 |
| `arcane` | 0~100 | 마법 지식, 의식 해석, 초자연 문제 해결 | 마법사, 수석 마법사, 마탑주 |
| `diplomacy` | 0~100 | 설득, 협상, 세력 조정 | 외교관, 대사, 왕국 재상 |
| `commerce` | 0~100 | 거래, 재정 운영, 자원 배분 | 상단주, 재무관, 왕실 재무관 |
| `leadership` | 0~100 | 조직 통솔, 책임감, 민심 결집 | 영주, 기사단장, 구국의 대공 |
| `craft` | 0~100 | 세밀한 제작, 생활 기술, 창의적 문제 해결 | 장인, 연금술사, 이색 또는 B급 전문직 |

#### 적성 증가 규칙

- 핵심 선택지와 사건 해결 결과가 적성 증가의 주된 근거다.
- 자유 대화에서 확인된 태그와 행동은 서버 규칙에 따라 한 번에 최대 2점까지만 보조적으로 반영한다.
- LLM은 적성 변화량을 직접 결정하지 않는다.
- 한 Act에서 하나의 적성이 증가할 수 있는 총량은 기본 15점으로 제한한다.
- 모든 적성은 0~100 범위로 제한하고, 적용된 규칙 ID를 이벤트 로그에 남긴다.
- 일반 UI에서는 적성 수치를 숨기고, 디버그 화면에서만 확인할 수 있게 한다.

#### 적성과 직업의 관계

직업 후보는 가장 높은 적성 하나만으로 결정하지 않는다. 상위 적성, 실제 업적, 직업 위상, 엔딩 톤을 함께 사용한다.

예시:

- `arcane` 높음 + 마법 사건 해결 + `legendary` → 마탑주 계열
- `martial` 높음 + 군사 위기 해결 + `accomplished` 이상 → 기사단장 계열
- `diplomacy`와 `leadership` 높음 + 높은 `legitimacy` → 왕국 재상 계열
- `commerce` 높음 + 재정 회복 → 상단주 또는 왕실 재무관 계열
- `craft`, `persuasive`, `eccentric` 조합 + `b_grade` → 영지민을 한데 모은 네일아티스트 같은 이색 전문직

### 2.5 NPC 관계 상태

각 NPC는 다음 데이터를 가진다.

- `trust`: 신뢰도 0~100
- `fear`: 두려움 0~100
- `suspicion`: 플레이어에 대한 의심 0~100
- `status`: `active`, `allied`, `hostile`, `departed`, `dead`
- `known_facts`: 해당 NPC가 대화에서 알게 된 사실 ID 목록
- `revealed_secrets`: 플레이어에게 공개한 비밀 ID 목록

LLM은 관계 변화의 힌트만 반환한다. 최종 변화량은 서버 규칙으로 계산한다.

### 2.6 15분 기승전결과 Act 구성

짧은 플레이에서도 하나의 완결된 이야기를 경험하도록 각 Act의 극적 기능과 목표를 명확히 나눈다.

| Act | 극적 기능 | 권장 시간 | 내용 | 주요 플레이 |
| --- | --- | ---: | --- | --- |
| Act 1 | 기 | 0:00~3:00 | 주인공이 영주에게 빙의하고 3년 뒤 균열로 영지가 멸망한다는 사실을 떠올린다. 에드윈의 보고를 통해 세 봉화와 영지의 부족한 자원을 확인한다. | 에드윈 자유 대화 최대 2회, 첫 준비 방침 선택 |
| Act 2 | 승 | 3:00~7:00 | 견습 마법사 리아와 함께 균열 대응 계획을 세운다. 군사 훈련, 봉인 연구, 외부 지원 중 무엇을 우선할지 결정한다. | 리아 자유 대화 최대 2회, 전략 선택 |
| Act 3 | 전 | 7:00~11:00 | 농부 마르타와 마력보리를 심으며 영지민의 평범한 삶을 경험한다. 평화로운 작업 직후 하늘에 균열의 전조가 나타나고 시간이 3년 뒤로 전환된다. | 생활 대화, 밭 클릭 미니게임, 자원 배분 선택 |
| Act 4 | 결 | 11:00~15:00 | 균열이 열리고 세 봉화 중 일부가 꺼진다. 제한시간 안에 최종 대응을 골라 영지의 운명과 주인공의 직업을 확정한다. | 위기 대화 선택적 1회, 20초 최종 선택, 이중 엔딩 |

#### Act별 감정 곡선

- 기: 당황과 위기 인식
- 승: 계획 수립과 성장의 기대
- 전: 영지민에게 정을 붙이는 평온함에서 재앙의 전조로 급전환
- 결: 누적된 준비의 회수, 영지 운명 확정, 직업 엔딩의 성취 또는 웃음

#### 시간 제한 원칙

- Act 1~3 자유 대화에는 실시간 타이머를 두지 않고 대화 가능 횟수만 제한한다.
- Act 4의 최종 대응 선택에만 기본 20초 제한을 둔다.
- 서버 또는 LLM 응답을 기다리는 동안 타이머는 정지한다.
- 시간 초과 시 아무 행동도 하지 않는 것이 아니라, 현재 상태에 맞는 안전한 기본 대응인 `주민 대피`를 자동 선택한다.

### 2.7 핵심 플레이 루프

1. 서버가 현재 Act와 게임 상태에 맞는 장면 및 NPC를 선택한다.
2. 클라이언트가 배경, NPC, 상황 설명을 표시한다.
3. 플레이어가 NPC에게 자유 텍스트를 입력한다.
4. 서버가 입력을 LLM에 전달하고 구조화된 대사 및 태그 후보를 받는다.
5. 서버가 후보를 검증하고 규칙표에 따라 허용된 상태, 성향, 관계, 직업 적성 변화만 적용한다.
6. 클라이언트가 NPC 대사, 표정, 상태 피드백을 표시한다.
7. 자유 대화 횟수가 끝나거나 조건이 충족되면 고정 선택지를 제시한다.
8. Act 3에서는 선택 결과에 따라 클릭 미니게임을 실행하고, 서버가 결과를 검증한다.
9. 서버가 선택 결과를 계산하고 다음 Act 또는 엔딩으로 이동한다.

### 2.8 사건 구성과 선택 규칙

#### MVP

발표용 데모에서는 기승전결과 15분 완주를 보장하기 위해 핵심 사건의 순서를 고정한다.

1. 멸망 예고와 영지 보고
2. 균열 대응 계획
3. 마력보리 농사
4. 균열 발생과 최종 대응

플레이어별 차이는 사건 자체를 바꾸기보다 다음 요소에서 만든다.

- 같은 NPC가 플레이어의 말투와 이전 선택을 기억해 다르게 반응한다.
- Act 2에서 선택한 전략에 따라 Act 3의 대사와 미니게임 보너스가 달라진다.
- 농사 과정에서 선택한 행동에 따라 식량, 민심, 마법, 제작 적성이 달라진다.
- 최종 위기의 사용 가능 선택지와 성공 확률이 누적 상태에 따라 달라진다.
- 영지 운명과 직업 엔딩 조합이 달라진다.

#### 데모 이후 확장

완성된 데모를 발전시킬 때는 `고정 핵심 사건 + 조건부 개인 사건 + 분위기 사건`의 3계층으로 확장한다.

| 계층 | 기능 | 선택 방식 |
| --- | --- | --- |
| `core` | 기승전결과 메인 목표를 유지 | 항상 고정 순서로 발생 |
| `personal` | 적성, 관계, 부족한 자원에 맞춘 개인화 | 조건을 만족한 후보 중 가중치 선택 |
| `flavor` | 식사, 축제, 수리, 산책 등 생활감 제공 | 세션 시드 기반 선택 |

개인화 사건은 LLM이 즉석에서 규칙까지 만들지 않는다. 콘텐츠 파일에 정의된 사건 중 서버가 조건을 판정해 선택하고, LLM은 선택된 사건의 대사만 변주한다. 같은 세션 시드와 상태에서는 같은 사건이 선택되어야 한다.

### 2.9 승패 판정

MVP 기본 판정 규칙:

- 완전 생존: `military`, `treasury`, `legitimacy`, `ward` 중 3개 이상이 기준치 이상이며 선택한 최종 대응 조건 충족
- 불완전 생존: 주민 또는 영지는 지켰지만 큰 피해, 외부 세력 종속, 일부 지역 포기 중 하나가 발생
- 영지 멸망: 생존 조건 미달 또는 치명적 선택 발생
- 특수 결과: 특정 태그와 관계, 선택 조합이 설정 파일의 특수 조건과 일치

기준치는 설정 파일에서 조정 가능해야 한다. 엔딩 판정 결과에는 반드시 근거 ID 목록을 포함한다.

## 3. 직업 및 후일담 엔딩 시스템

### 3.1 설계 목표

엔딩 직업은 플레이어의 성과와 플레이 방식에 대한 보상이다. 뛰어난 성과를 낸 플레이어는 기사, 기사단장, 왕국 재상, 마탑주처럼 강함과 위상이 분명한 직업을 얻을 수 있어야 한다. 동시에 기행, 독특한 해결 방식, 희귀한 태그 조합을 만든 플레이어에게는 예상 밖의 이색 직업이나 B급 직업이 나올 수 있다.

핵심은 모든 엔딩을 웃긴 결과로 만드는 것이 아니라, **정통 성장 판타지의 성취감과 맥락 있는 의외성을 함께 제공하는 것**이다.

정통 엔딩 예:

> 마력 연구와 외교를 모두 성공시킨 마탑주  
> 지식으로 영지를 구하고 왕국의 마법 질서를 다시 세웠다.

B급 엔딩 예:

> 뛰어난 입담으로 분열된 영지민을 하나로 모은 네일아티스트  
> 갈라진 민심도, 갈라진 손톱도 그냥 두지 않는다.

나쁜 예:

> 우주비행사  
> 플레이 기록과 아무 관련이 없으며 설명도 없다.

### 3.2 이중 구조

엔딩은 다음 두 층으로 구성한다.

#### A. 결정론적 결과층

서버가 확정한다.

- 영지 운명
- 직업 위상 등급
- 엔딩 톤
- 상위 직업 적성 2개와 적성 근거 업적
- 가장 높은 성향
- 대표 행동
- 핵심 관계 결과
- 가장 큰 성공과 실패
- 플레이어가 사용한 해결 방식
- 엔딩 희귀 조건 충족 여부

#### B. 생성 표현층

LLM이 생성한다.

- 플레이 성과와 성향에 맞는 최종 직업명
- 칭호
- 해당 직업이 된 인과관계 설명
- 3~5문장의 후일담
- 공유용 한 줄 문구

생성 표현층은 결정론적 결과층을 변경할 수 없다.

#### 영지 운명 후보

직업 엔딩과 영지 운명은 독립적으로 조합한다. 영지를 완벽히 지켜야만 좋은 직업을 얻는 것은 아니며, 영지가 무너져도 주민을 살린 플레이는 분명한 성취로 인정한다.

| 결과 ID | 의미 |
| --- | --- |
| `self_saved` | 자체 준비와 주민 협력으로 영지를 지킴 |
| `damaged_survival` | 큰 피해를 입었지만 영지와 주민 공동체가 살아남음 |
| `external_aid` | 왕국 또는 외부 세력의 도움으로 생존하지만 자치권이나 자원을 일부 잃음 |
| `people_evacuated` | 영지는 멸망했지만 주민 대부분을 안전하게 대피시킴 |
| `absorbed` | 영지는 다른 세력에 편입되지만 주민의 삶은 유지됨 |
| `destroyed` | 영지와 주민 모두 큰 피해를 입음 |

### 3.3 직업 위상과 엔딩 톤

직업의 강함과 분위기를 하나의 `absurdity_level`로 묶지 않는다. 서버는 `career_rank`와 `ending_tone`을 별도로 판정한다.

#### 직업 위상 등급

| 등급 | 판정 방향 | 예시 |
| --- | --- | --- |
| `fallen` | 영지 멸망 또는 치명적 실패 | 몰락 귀족, 떠돌이 용병 |
| `survivor` | 영지를 간신히 지키거나 개인적으로 생존 | 기사, 상단 직원, 지방 관리 |
| `accomplished` | 주요 목표를 다수 달성 | 기사단장, 왕실 외교관, 수석 재무관 |
| `legendary` | 높은 자원, 핵심 관계, 특수 조건을 함께 달성 | 마탑주, 왕국 재상, 구국의 대공 |

#### 엔딩 톤

| 톤 | 방향 | 예시 |
| --- | --- | --- |
| `orthodox` | 정통 판타지와 성장 보상 | 기사, 마법사, 외교관 |
| `prestige` | 높은 성과에 맞는 권력과 명예 | 기사단장, 마탑주, 왕국 재상 |
| `unexpected` | 맥락은 있지만 예상 밖인 전문 직업 | 귀족 전문 이미지 컨설턴트 |
| `b_grade` | 의도적으로 과장된 B급 조합 | 영지민을 한데 모은 네일아티스트 |

`career_rank`는 플레이 성과로 결정하며 LLM이 낮추거나 높일 수 없다. `ending_tone`은 성향 태그, 선택 방식, 기행 점수, 희귀 조건을 기반으로 서버가 결정한다. 뛰어난 플레이어는 `prestige` 톤을 얻을 수 있으며, B급은 가능한 결과 중 하나일 뿐 기본값이 아니다.

직업군은 `career_affinities`와 검증된 업적으로 결정한다. 높은 적성만 있고 관련 업적이 없으면 최고 직업을 해금하지 않는다. 예를 들어 `arcane` 수치가 높더라도 핵심 마법 사건을 해결하지 않았다면 마탑주가 아니라 일반 마법사 또는 연구자 후보까지만 허용한다.

#### 직업군 판정 예시

| 조건 | 허용 직업 예시 |
| --- | --- |
| `martial >= 70` + 군사 핵심 업적 + `career_rank = legendary` | 구국의 기사, 기사단장, 왕국 대장군 |
| `arcane >= 70` + 마법 핵심 업적 + `career_rank = legendary` | 마탑주, 왕실 대마법사 |
| `diplomacy >= 65` + `leadership >= 60` + 높은 정통성 | 왕국 재상, 대공, 연합의 중재자 |
| `commerce >= 65` + 재정 회복 업적 | 상단주, 왕실 재무관 |
| `craft >= 55` + `eccentric >= 5` + `ending_tone = b_grade` | 플레이 근거와 연결된 이색 전문직 |

### 3.4 직업 생성 필수 규칙

생성된 결과는 다음 조건을 모두 만족해야 한다.

1. 플레이 기록의 근거를 최소 2개 사용한다.
2. 직업과 근거 사이의 인과관계를 후일담에서 설명한다.
3. 직업명은 30자 이내를 권장한다.
4. `career_rank`와 `ending_tone`을 지키며, 높은 성과를 우스운 실패처럼 취급하지 않는다.
5. 단순히 무관한 명사를 무작위로 붙이지 않는다.
6. 차별, 혐오, 성적 모욕, 현실 범죄 미화 표현은 사용하지 않는다.
7. 실존 인물이나 상표를 직업명의 핵심 소재로 사용하지 않는다.
8. 같은 세션에서 생성된 후보끼리 의미상 중복되지 않는다.
9. JSON Schema를 통과하지 못한 결과는 사용하지 않는다.

### 3.5 생성 절차

1. 서버가 플레이 기록을 `EndingFacts`로 요약한다.
2. 서버가 플레이 성과로 `career_rank`를, 성향과 선택 방식으로 `ending_tone`을 판정한다.
3. LLM이 판정된 위상과 톤 안에서 서로 다른 직업 후보 3개를 반환한다.
4. 서버가 위상 일치 여부, 톤 일치 여부, 금칙어, 길이, 근거 수, 중복 여부를 검증한다.
5. 유효 후보 중 맥락 점수가 가장 높은 후보를 우선하고, 동점일 때 참신성 점수를 사용한다.
6. 유효 후보가 없으면 1회 재생성한다.
7. 재생성도 실패하면 위상과 톤에 맞는 고정 직업 템플릿을 사용한다.

참신성 점수는 복잡한 AI 평가가 아니라 다음 단순 규칙으로 시작한다.

- 판정된 직업 위상과 일치함: 필수
- 판정된 엔딩 톤과 일치함: 필수
- 플레이 근거가 직업 능력과 직접 연결됨: +3
- 사용 근거가 3개 이상임: +1
- 기존 세션 결과와 직업명이 다름: +1
- `unexpected` 또는 `b_grade` 톤에서 의외의 결합이 있음: +1
- 높은 성과를 이유 없이 낮은 위상으로 표현함: 후보 탈락
- 금칙어 또는 설명 불가능한 소재: 후보 탈락

### 3.6 세계관 처리

`unexpected` 또는 `b_grade` 톤에서는 현대 직업이 등장하는 감성을 허용한다. 정통 엔딩에서는 본편 세계관에 맞는 직업과 명칭을 우선한다. 현대 직업 엔딩은 본편 이후를 과장하여 기록한 메타적 후일담으로 연출하며, 본편 NPC가 갑자기 현대 지식을 아는 방식으로 세계관을 깨지 않는다.

권장 문구:

> 후대의 역사가들은 그 기묘한 생업을 무엇이라 불러야 할지 몰랐다. 빙의자는 익숙한 단어 하나를 남겼다. 네일아티스트.

### 3.7 엔딩 결과 화면

결과 화면은 캡처와 공유를 고려해 한 화면에 핵심 정보가 들어가야 한다.

- 최종 직업명
- 칭호
- 영지 운명
- 결정적 기록 3개
- 성향 태그 3개
- 공유용 한 줄 문구
- 다시 플레이 버튼
- 결과 이미지 저장 버튼은 MVP 이후 선택 기능

실제 통계가 없는 상태에서 가짜 백분위나 가짜 희귀도를 표시하지 않는다. 통계가 구현되기 전에는 `일반`, `희귀`, `특수`처럼 규칙 기반 등급만 사용한다.

## 4. 콘텐츠 기본안

### 4.1 확정 메인 스토리

현대인인 주인공은 자신이 읽었던 웹소설 속 북부 영주에게 빙의한다. 소설에서 이 영지는 3년 뒤 북부 하늘에 열린 마력 균열과 마물의 습격으로 사라진다. 당시 세 개의 방어 봉화가 모두 꺼졌다는 사실만 기록되어 있으며, 주민을 끝까지 지킨 사람의 이름은 남지 않았다.

현재 영지는 빚에 시달리고 기사단은 사실상 해체되었으며 봉화는 고장 나 있다. 주인공은 제한된 자원 안에서 군사 대비, 봉인 연구, 외부 지원, 주민 결속 중 무엇을 우선할지 선택한다. 그 과정에서 영지민과 마력보리를 심으며 자신이 지키려는 것이 단순한 영지가 아니라 이곳의 평범한 삶임을 깨닫는다.

3년 뒤 균열이 열리면 플레이어가 준비한 상태와 관계에 따라 봉화를 재가동해 직접 막거나, 외부 지원을 받아 영지를 살리거나, 주민만 대피시키거나, 모든 것을 잃게 된다. 이후 동일한 기록을 바탕으로 주인공이 어떤 직업과 삶을 얻었는지 보여준다.

### 4.2 주요 NPC

| ID | 역할 | 겉으로 보이는 성격 | 숨겨진 기능 |
| --- | --- | --- | --- |
| `steward_edwin` | 집사, 전 기사단 부단장 | 현실적이고 무뚝뚝함 | 재정 보고, 군사 훈련, 주민 대피 계획의 핵심 |
| `mage_lia` | 견습 마법사 | 호기심이 많지만 자신감이 부족함 | 균열 감지, 봉화 수리, 마법 직업군의 핵심 |
| `farmer_marta` | 농부 대표 | 다정하지만 할 말은 함 | 마력보리 농사, 영지민 결속, 생활 직업군의 핵심 |

세 NPC는 모두 범인 후보가 아니다. 갈등은 각자가 중요하게 생각하는 대비책과 자원 배분이 다르다는 데서 발생한다.

### 4.3 Act별 필수 장면

| Act | 배경 | 핵심 갈등 | 필수 회수 요소 |
| --- | --- | --- | --- |
| 1 | 빚 문서가 쌓인 영주 집무실 | 지금 가진 돈을 어디에 먼저 쓸 것인가 | 세 봉화, 3년이라는 기한, 에드윈의 불신 |
| 2 | 고장 난 북부 봉화탑 | 군사, 봉인 연구, 외부 지원 중 무엇을 우선할 것인가 | 리아의 균열 감지 능력, 선택한 주력 전략 |
| 3 | 주민 공동밭 | 부족한 물과 종자를 어떻게 배분할 것인가 | 마력보리, 마르타와 주민들의 신뢰, 균열의 전조 |
| 4 | 붉게 갈라진 하늘 아래 성벽 | 직접 방어, 봉인, 외부 지원, 주민 대피 중 무엇을 택할 것인가 | 이전 Act의 선택과 관계를 모두 사용 |

### 4.4 Act별 최소 콘텐츠

각 Act에는 다음이 필요하다.

- 도입 내레이션 1개
- 주요 NPC 1~2명
- 자유 대화 상황 1개
- 고정 선택지 3개
- 선택지별 상태 변화 규칙
- 표정 상태 3개 이상
- 성공 피드백과 실패 피드백
- 다음 Act 연결 조건

### 4.5 고정 선택지 예시

Act 2의 대응 계획:

- A: 남은 자금을 기사단 재건과 주민 대피 훈련에 사용한다.
- B: 리아의 봉화 수리와 균열 봉인 연구에 투자한다.
- C: 왕국과 상단에 지원을 요청할 협상 비용으로 사용한다.

같은 B를 선택해도 리아를 격려했는지, 명령했는지, 엉뚱한 아이디어를 보탰는지에 따라 관계와 적성이 달라질 수 있다. 그러나 핵심 자원 변화는 서버 규칙표로 계산한다.

### 4.6 농사 미니게임

마력보리 농사는 `밭 정리 → 씨앗 배치 → 물 배분`의 세 단계로 진행한다. 전체 소요 시간은 60~90초를 목표로 한다.

- 밭의 돌과 잡초를 클릭해 제거한다.
- 제한된 칸에 씨앗을 배치한다.
- 남은 물을 선택한 구역에 분배한다.
- 완벽한 조작을 요구하지 않으며 실패해도 이야기는 계속된다.

행동 방향에 따른 대표 보상:

| 행동 | 주요 변화 | 직업 근거 예시 |
| --- | --- | --- |
| 효율적으로 넓은 밭을 완성 | `treasury`, `commerce` | 보급 책임자, 상단주 |
| 주민들과 같은 속도로 작업 | `legitimacy`, `leadership` | 존경받는 영주, 공동체 지도자 |
| 마력을 사용해 재배 | `ward`, `arcane` | 마법사, 마탑주 |
| 도구나 품종을 개량 | `craft` | 장인, 연금술사, 이색 전문직 |
| 대화와 농담으로 분위기를 결집 | `persuasive`, `eccentric` | 광대, 이야기꾼, B급 전문직 |

마력보리는 균열을 해결하는 필수 열쇠가 아니다. 최종전에서 식량, 주민 사기 또는 봉화 연료 중 플레이 방식에 맞는 작은 보너스를 제공한다.

```json
  }

```

### 7.1 세션 시작

`POST /api/v1/sessions`

요청:

```json
{
  "mode": "live"
}
```

응답:

```json
{
  "sessionId": "uuid",
  "act": 1,
  "timeLabel": "멸망 3년 전",
  "scene": {
    "backgroundId": "study_night",
    "npcId": "steward_edwin",
    "npcEmotion": "neutral",
    "narration": "눈을 뜬 순간, 3년 뒤 붉게 갈라질 북부의 하늘이 떠올랐다."
  },
  "dialogueRemaining": 2
}
```

### 7.2 자유 대화

`POST /api/v1/sessions/{sessionId}/dialogues`

요청:

```json
{
  "npcId": "steward_edwin",
  "text": "기사보다 주민 대피 훈련부터 시작하면 안 될까?",
  "idempotencyKey": "client-generated-uuid"
}
```

응답:

```json
{
  "dialogue": "성을 포기하자는 말씀인 줄 알았습니다. 하지만 피난로를 먼저 정비하는 데는 동의합니다.",
  "emotion": "surprised",
  "feedback": "에드윈은 영주의 명령이 아니라 주민의 이름이 먼저 나온 것을 기억했다.",
  "acceptedTags": ["kind", "pragmatic"],
  "careerFeedback": "사람을 먼저 살리는 지휘 방식이 드러났다.",
  "dialogueRemaining": 1,
  "choicesAvailable": false
}
```

`acceptedTags`와 실제 적성 변화량은 디버그 빌드에서만 직접 표시한다. 일반 UI에서는 표정, `feedback`, `careerFeedback` 같은 서사적 문장으로 전달한다.

### 7.3 선택지 조회

`GET /api/v1/sessions/{sessionId}/choices`

### 7.4 선택지 제출

`POST /api/v1/sessions/{sessionId}/choices`

요청:

```json
{
  "choiceId": "act1_interrogate",
  "idempotencyKey": "client-generated-uuid"
}
```

응답에는 선택 결과 내레이션, 상태 피드백, 다음 Act 장면 또는 엔딩 가능 여부를 포함한다.

### 7.5 현재 세션 복구

`GET /api/v1/sessions/{sessionId}`

클라이언트 재실행 또는 통신 오류 후 현재 장면과 입력 가능 상태를 복구한다.

### 7.6 엔딩 생성

`POST /api/v1/sessions/{sessionId}/ending`

서버는 먼저 엔딩 결과층을 판정하고, 그 결과를 기반으로 직업 후보와 에필로그를 생성한다. 이미 생성된 엔딩이 있으면 같은 결과를 반환한다.

### 7.7 상태 확인

`GET /health`

데이터베이스와 기본 서버 상태를 확인한다. 외부 API의 상세 오류나 비밀 설정은 노출하지 않는다.

### 7.8 미니게임 결과 제출

`POST /api/v1/sessions/{sessionId}/minigames/{miniGameId}/complete`

클라이언트가 클릭 횟수, 성공 칸, 사용 시간, 선택한 배분안을 제출한다. 서버는 현재 사건, 허용 범위, 중복 제출 여부를 검증한 뒤 결과 등급과 상태 변화를 계산한다. 클라이언트가 최종 보상 수치를 직접 지정할 수 없게 한다.

## 8. LLM 통합 명세

### 8.1 공통 원칙

- OpenAI API 호출은 서버에서만 수행한다.
- 사용자 입력은 시스템 지침과 명확히 분리한다.
- NPC가 알 수 없는 정보는 프롬프트에 포함하지 않는다.
- 전체 대화 원문을 계속 누적하지 않고 최근 대화와 검증된 요약을 사용한다.
- 모델 출력은 신뢰하지 않고 스키마 및 비즈니스 규칙을 검증한다.
- 모델명, 시간 제한, 최대 출력 길이는 환경 설정으로 관리한다.

### 8.2 NPC 대화 출력

```json
{
  "npcDialogue": "string",
  "emotion": "neutral|happy|angry|nervous|sad|surprised",
  "suggestedTags": [
    {
      "tag": "observant",
      "confidence": 0.91,
      "evidence": "주민 대피를 먼저 제안하며 현실적인 우선순위를 제시함"
    }
  ],
  "relationshipHint": {
    "trust": -1,
    "fear": 2,
    "suspicion": 0
  },
  "newSummary": "플레이어가 숨겨진 장부를 언급하며 집사를 압박했다."
}
```

검증 규칙:

- `npcDialogue`: 1~300자
- `emotion`: 허용 enum만 사용
- `suggestedTags`: 최대 3개, 허용 태그만 수용
- `confidence`: 0~1
- 관계 힌트: 각 -2~2, 서버 규칙으로 재계산 가능
- `newSummary`: 1~500자

### 8.3 EndingFacts 입력

```json
{
  "territoryResult": "영지 생존",
  "dominantTrait": "observant",
  "signatureActions": [
    "금지된 마법 의식의 구조를 해독함",
    "마법사 길드와 협상해 영지 방어 결계를 완성함"
  ],
  "relationshipResult": "마법사 길드와 기사단의 공동 지지",
  "greatestFailure": "상단과의 거래에서 일부 자산을 잃음",
  "topCareerAffinities": [
    { "affinity": "arcane", "score": 84 },
    { "affinity": "leadership", "score": 72 }
  ],
  "careerEvidence": [
    "금지된 마법 의식의 구조를 해독함",
    "마법사 길드와 기사단을 공동 지휘함"
  ],
  "careerRank": "legendary",
  "endingTone": "prestige",
  "surpriseLevel": 2,
  "allowedTone": "정통 성장 판타지의 성취감을 유지함"
```

### 8.4 직업 후보 출력

아래 JSON은 `prestige` 톤의 예시다. `unexpected` 또는 `b_grade` 톤도 같은 필드 구조를 사용하되, 서버가 판정한 직업 위상을 그대로 유지해야 한다.

```json
{
  "candidates": [
    {
      "occupationName": "북부 결계의 마탑주",
      "title": "멸망의 공식을 다시 쓴 자",
      "usedEvidence": [
        "금지된 마법 의식의 구조를 해독함",
        "마법사 길드와 협상해 영지 방어 결계를 완성함"
      ],
      "causalExplanation": "마법 의식을 해독한 통찰과 서로 반목하던 세력을 결집한 지도력이 마탑을 이끌 자격으로 이어졌다.",
      "epilogue": "멸망의 날, 완성된 결계는 영지 전체를 감쌌다. 전쟁이 끝난 뒤 마법사들은 그에게 비어 있던 마탑주의 자리를 바쳤다. 그는 영지를 구한 공식을 새로운 마법 교육의 첫 장에 남겼다.",
      "shareLine": "그는 운명을 예언하지 않았다. 계산을 끝내고 고쳐 썼다."
```

### 8.5 프롬프트 인젝션 대응

- 사용자 입력에 포함된 명령은 대화 내용으로만 취급한다.
- 사용자 입력으로 시스템 프롬프트, 숨겨진 설정, 다른 NPC의 비밀을 공개하지 않는다.
- LLM이 반환한 선택지 ID, 상태값, 비밀 ID는 서버의 허용 목록과 대조한다.
- 모델이 게임 종료나 승리를 선언해도 서버 상태가 일치하지 않으면 무시한다.

## 10. 장애 및 예외 처리

### 10.1 LLM 호출 정책

- 요청 시간 제한을 설정한다.
- 시간 초과 또는 일시 오류 시 최대 1회 재시도한다.
- 재시도에는 동일한 `idempotencyKey`를 사용한다.
- JSON 검증 실패 시 교정 재요청을 최대 1회 수행한다.
- 최종 실패 시 고정 폴백 콘텐츠를 반환한다.

### 10.2 필수 폴백

- NPC별 일반 응답 3개 이상
- Act별 선택지 연결용 응답
- 기본 대화 요약
- 기본 태그 없음 처리
- 직업 위상과 엔딩 톤 조합별 기본 직업 템플릿
- 기본 에필로그

### 10.3 Mock 모드

Mock 모드는 외부 API 없이 전체 게임을 끝까지 플레이할 수 있어야 한다.

- 세션 시드와 요청 내용에 따라 재현 가능한 응답 반환
- 정상 응답, 지연, 잘못된 JSON, 시간 초과 상황을 선택적으로 시뮬레이션
- 발표 빌드에서 설정 메뉴 또는 시작 옵션으로 활성화
- 라이브 모드와 동일한 인터페이스 사용

### 10.4 중복 처리

- 대화와 선택지 요청에 `idempotencyKey`를 요구한다.
- 같은 키의 요청이 재전송되면 기존 결과를 반환한다.
- 한 세션에서 동시에 두 개의 진행 요청을 처리하지 않는다.

## 11. 보안 및 운영

- API 키는 환경 변수 또는 개발 환경의 비밀 저장소에서 관리한다.
- 저장소에 실제 API 키를 커밋하지 않는다.
- 클라이언트가 서버의 LLM 엔드포인트를 임의 호출하지 못하도록 세션과 현재 턴을 검증한다.
- 사용자 입력 길이를 제한한다. MVP 권장 최대 길이는 300자다.
- 세션별 및 IP별 요청 제한을 둔다.
- 로그에는 API 키, 전체 시스템 프롬프트, 불필요한 개인정보를 기록하지 않는다.
- 개발 로그와 발표 로그의 상세 수준을 분리한다.
- 콘텐츠와 프롬프트에 버전을 부여하여 재현 가능성을 확보한다.

- LLM 정상 응답 처리

- Mock Provider와 Live Provider의 동일 계약 준수

### 15.3 시나리오 테스트

1. 높은 군사 성과와 충성 확보 → 기사단장 또는 구국의 기사 계열
2. 높은 봉인 준비·마법·외교 성과와 특수 조건 달성 → 마탑주 또는 왕국 재상 계열
3. 달변과 기행 중심 플레이 → 설득 능력과 연결된 이색 또는 B급 직업
4. 자산 중심 플레이 → 상단주, 재무관 또는 거래 능력을 비튼 이색 직업
5. 낮은 성과 플레이 → 실패 수준에 맞는 직업 위상을 유지하되 플레이 근거 반영
6. 모든 LLM 호출 실패 → 위상과 톤에 맞는 고정 콘텐츠로 정상 엔딩 도달
7. 최종 선택 시간 초과 → 주민 대피 자동 선택 후 정상 엔딩 도달
8. 농사 미니게임 낮은 점수 → 진행 중단 없이 작은 보상 또는 무보상으로 Act 4 진입

### 15.4 엔딩 품질 체크리스트

- [ ] 직업 위상이 플레이 성과와 일치하는가
- [ ] 직업군이 상위 `career_affinities`와 실제 업적에 의해 뒷받침되는가
- [ ] 엔딩 톤이 플레이 성향과 선택 방식에 어울리는가
- [ ] `unexpected` 또는 `b_grade`라면 직업명이 적절히 예상에서 벗어나는가
- [ ] 플레이 기록이 최소 2개 반영되었는가
- [ ] 직업이 된 이유를 한 번 읽고 이해할 수 있는가
- [ ] 플레이어를 모욕하지 않는가
- [ ] 엔딩이 영지 운명과 충돌하지 않는가
- [ ] 공유 문구가 한 문장으로 기억되는가
- [ ] 결과 카드에서 글자가 잘리지 않는가

## 17. Definition of Done

기능은 다음 조건을 모두 충족해야 완료로 간주한다.

- 정상 경로가 구현되어 있다.
- 잘못된 입력과 외부 API 실패 경로가 구현되어 있다.
- 자동 테스트 또는 재현 가능한 수동 테스트 절차가 있다.
- 서버가 게임 상태를 최종 결정한다.
- LLM 출력은 스키마와 허용 목록 검증을 통과한다.
- 로그로 판정 근거와 오류 원인을 확인할 수 있다.
- Mock 모드에서도 동일한 기능 계약으로 실행된다.
- 사용자에게 오류 원문이나 비밀 정보가 노출되지 않는다.
- 관련 명세 또는 설정 파일이 구현과 일치한다.

## 18. 구현 시작 시 권장 첫 작업

Codex는 다음 순서로 첫 작업을 진행한다.

1. 저장소 구조와 실행 환경 확인
2. `Session`, `GameEvent`, `NpcState`, `TraitScore`, `CareerAffinity` 도메인 모델 생성
3. Mock Provider 인터페이스와 응답 DTO 생성
4. 세션 생성 API 구현
5. 단일 자유 대화 API 구현
6. 단일 선택지 적용과 상태 변화 구현
7. Godot에서 위 API를 호출하는 세로 슬라이스 구현
8. 테스트 통과 후 4개 Act로 확장

첫 세로 슬라이스가 완성되기 전에는 실제 LLM 연동이나 화려한 UI를 우선 구현하지 않는다.
